# 複数パターン瞬き認識（揺れのあるキャラクター向け）

**瞬き複数パターン認識**（`builtin.recognition.blink-multi-exemplar`）は、待機モーションなどで頭が左右に揺れ、
閉眼のドット単位の見え方が瞬きごとに少しずつ変わるキャラクター向けの認識方式です。
既存の **固定テンプレート瞬き認識** と **瞬き特徴認識** は互換性のためそのまま残っています。

## なぜ固定テンプレートでは足りないのか

揺れがあると、目の位置が数 px ずれ、白目と黒目の比率も揺れの位相に応じて変わります。
開眼 1 枚と閉眼 1 枚だけでは「揺れの端の開眼」と「揺れの中央の閉眼」の区別がつかず、
誤検出か取りこぼしのどちらかが起きます。瞬きが 1〜2 フレーム（60fps で 16〜33ms）しかない場合、
平滑化で吸収することもできません。

## 収束のさせ方

揺れを位置合わせで消すのではなく、**採取データで揺れ全体を覆い、閾値は未学習データで自動校正**します。

| 要素 | 内容 |
|---|---|
| 開眼パターン | 録画した開眼フレームから、揺れの全位相を覆うよう最遠点選択で 8〜16 枚を自動選択 |
| 閉眼パターン | 指定した全瞬きの閉眼フレームを使い、姿勢の違う複数パターンを保持（最大 12 枚） |
| 照合 | ネイティブ解像度のカラー（BGR）で、目 ROI ± 探索半径の範囲を正規化相関で照合。各パターンの最大値を採用 |
| 判定 | 閉眼 = 閉眼一致度が下限以上 かつ（閉眼最大 − 開眼最大）が閾値超 かつ 開眼最大が上限未満。開眼 = 開眼最大が上限以上。それ以外は判定不能（発火しない） |
| 探索半径 | 開眼フレームの実測ずれ量から 4〜8px で自動決定 |
| 閾値校正 | 開眼は連続時間ブロック単位、閉眼は瞬きイベント単位でデータを分け、学習に使っていない側で閾値を決めて検証 |
| 品質ゲート | 未学習側で誤検出 0・瞬き取りこぼし 0・分離幅 0.02 以上で合格。0.05 未満や瞬き 2 回だけの場合は注意表示 |

オンラインでの自動追加学習は行いません（誤った学習で汚染されるのを避けるため）。

## セットアップ手順

1. 認識プロファイルを作成または読み込み、本体の **瞬き観測セットアップ** を開く
2. **1. プレビュー開始** を押し、プレビュー上で目をドラッグして ROI を指定する（目の周辺だけ・最大 160px 四方）
3. **複数パターン（推奨）** タブを開き、揺れが数周期入り、瞬きが **3 回以上**（できれば揺れの位置が違うもの）含まれるまで録画する
4. **A. 履歴を取り込む** — 履歴の全フレームから目の周辺だけをコピーします。実効 fps が低い場合は警告されます
5. **B. 閉眼候補を検出** — 「普段の見え方と大きく違うフレーム」を候補として提示します（連続フレームは 1 件にまとめます）
6. 候補ごとに直前画像と候補画像を見比べ、`閉眼` / `開眼（誤候補）` / `除外` を選ぶ
   - 半目や遮蔽、エフェクトなど判断に迷うものは `除外`
   - 見落とされた閉眼は、履歴スライダーでそのフレームを表示して **選択履歴を閉眼に追加**
7. **C. 自動校正・品質検証** — 合格すると分離幅などの結果が表示されます
8. **D. モデルを反映** し、**自動認識設定を開く** からプロファイルを保存する

ROI を選び直すと、取り込み済みデータと校正結果は破棄されます。

## 不合格・注意が出たとき

- **閉眼イベントが不足**: 瞬きを 2 回以上（推奨 3 回以上）含めて録画し直してください
- **開眼フレームが不足**: 揺れが数周期入るよう、長めに録画してください
- **未学習の瞬きを取りこぼし / 誤検出**: 候補の判定ミス（半目を閉眼にした等）を見直すか、揺れの位置が違う瞬きを追加で録画してください
- **分離幅が小さい**: ROI を目だけに絞る、または瞬きを追加すると改善することがあります

## 観測中の動作とラベル

| ラベル | 意味 |
|---|---|
| `blink-open` | 開眼（瞬き検出の準備完了） |
| `blink-closed` | 閉眼。開眼で準備完了した後の最初の閉眼フレームで 1 回だけイベントになります |
| `blink-unknown` | 判定不能。発火しません。`UnknownGraceFrames` を超えて続くと準備状態を解除します |
| `blink-reacquiring` | 準備前（`RearmOpenFrames` 回連続の開眼待ち） |
| `blink-model-*` | モデルの欠落・破損・版違い、入力寸法・ROI・画素形式の不一致 |

二度瞬き（約 0.2 秒間隔）はそれぞれ別のイベントとして通知されます。1 回の瞬きとして扱いたい場合は
送信設定の瞬き集約（必要回数・集約時間）を使ってください。

閾値パラメーター（閉眼相関差・開眼類似度上限・閉眼最低一致度）は空欄なら校正値を使います。
値を入れるとモデルの校正値より優先されます（モデルのハッシュ検証対象外）。

## 制約

- カラー入力（BGR/BGRA）が必要です。グレースケール入力ではエラーになります
- 1 フレームの瞬きは、取得経路の間引きや処理落ちで失われることがあります。実効 fps が 45 を下回る環境では取りこぼしに注意してください
- カメラの大きな移動・拡大縮小や、キャラクターの立ち位置変更があった場合は再セットアップしてください

## 開発者向け: 回帰テスト用フィクスチャ

`BlinkObserverTool.BlinkRecognition.Tests\Fixtures\blink-sway-forest.bgr24.gz` は参照動画の顔周辺 64x56 を
BGR24 で全 1822 フレーム保存したものです。メタデータ（切り出し位置、目 ROI、閉眼フレーム、学習範囲）は同名の
JSON にあります。AV1 動画は OpenCV の FFmpeg バックエンドで読めないため、抽出は
`build\tools\extract-blink-fixture.py`（Media Foundation バックエンド使用）で行います。テストは先頭 480 フレーム
（瞬き 3 回）だけで校正し、残り 7 回の未学習の瞬きを含む全 10 回を誤検出なしで検出することを確認します。
